## 4. Per-change Rust impact

### 4.1 GFM punctuation flanking fix (`443861f`)

**Python change:** `CustomStrikethrough` in `flowmark_markdown.py` overrides `find()` to
filter regex matches by the full GFM flanking delimiter rules, fixing
`~100 (~200)` → incorrectly producing `~~100 (~~200)`. Adds 10 new tests in
`test_strikethrough.py`.

**Rust impact: NONE for code; tests-only port.**

The Rust formatter uses `comrak`, whose strikethrough implementation already follows the
full GFM flanking rules (whitespace and punctuation). Verified empirically — every input
from the 10 new Python tests was run through `target/release/flowmark`:

| Input | Output (Rust v0.2.6) | Match Python v0.6.5 |
| --- | --- | --- |
| `~100 (~200)` | `~100 (~200)` | yes |
| `100 (~200)` | `100 (~200)` | yes |
| `~100 (x ~200)` | `~100 (x ~200)` | yes |
| `(~~text~~) end` | `(~~text~~) end` | yes |
| `"~~text~~" end` | `"~~text~~" end` | yes |
| `~~hello!~~ end` | `~~hello!~~ end` | yes |
| `~100 [~200]` | `~100 [~200]` | yes |

**Action:** Port the 10 new tests to `tests/test_strikethrough.rs`.

## 6. Cross-binary churn investigation

The user reported diff churn between Python and Rust binaries on three example inputs
(TODO.md list items with semantic line breaks; runbook with curly-quote content;
performance-notes paragraphs). Each example was run through Python flowmark v0.6.5 and
Rust flowmark v0.2.6 (current parity baseline v0.6.4):

- All three examples produce **byte-identical output** between the two binaries.

Conclusion: the user's observed churn is from running **mismatched flowmark versions**
across previous formatting passes (e.g., an older Python or Rust version that had
different wrapping behavior). Once both binaries are at the same parity surface
(v0.6.5 / flowmark-rs at this sync), the churn disappears.

## 9. User churn examples — confirmed parity

The user reported diff churn between Python and Rust binaries on three example
documents (TODO list with semantic breaks; runbook with curly quotes; performance
notes paragraphs). All three were tested with Python flowmark v0.6.5 and the current
Rust release binary:

| Example | Python v0.6.5 vs Rust output | Notes |
| --- | --- | --- |
| TODO.md list items | byte-identical | Semantic break + curly quotes both render the same |
| Browser streaming runbook | byte-identical | "Tree partial: walker hit the file cap…" with curly quotes preserved |
| Performance notes paragraphs | byte-identical | Same wrap+semantic placement |

Conclusion: the user's churn was from running mismatched flowmark versions in
sequence (older Python or Rust producing different intermediate output). Bumping
flowmark-rs to v0.6.5 parity, and ensuring both tools are at the same version when
formatting, eliminates the churn.
