## Method

Followed the Mode B playbook with the **bidirectional library-divergence check**: rather
than trusting the upstream diff, every changed behavior was probed against the *built
Rust binary* to separate real parity gaps from cases comrak already handles.
Of the six library-relevant upstream changes, two were real Rust gaps fixed here, two
were already correct in Rust (tests ported only), and the rest are new CLI surface
(ported) or Python library/packaging (excluded).
A 33-file × 3-mode parity spot-check over the repo’s own Markdown found **zero new
divergences** — the only diffs are the pre-existing, documented upstream Python
escaped-backtick bug (`fmr-qmd8`, where Rust is the correct side).

## End-to-end skill-install coverage (tryscript)

`tests/tryscript/verbose-docs.tryscript.md` is expanded from 5 to **14 golden
scenarios**. V1-V12 mirror upstream v0.7.2 (skill output + the cross-agent `--surfaces`
install: default all-three, each single surface, `all`, a subset, and the unknown-value
exit code). V2 is adapted to the Rust port’s own `--docs` README. V13-V14 are **new**:
they install into a fresh sandbox project and read the installed
`.claude/skills/flowmark/SKILL.md` and `AGENTS.md` to assert the *content and location*
(frontmatter, the `DO NOT EDIT` format stamp, the marker-bounded block), not just
`test -f` existence.
Upstream covers existence only, so the content-verification idea is filed as
[jlevy/flowmark#61](https://github.com/jlevy/flowmark/issues/61) to backfill the Python
reference and keep both tryscript suites aligned.
