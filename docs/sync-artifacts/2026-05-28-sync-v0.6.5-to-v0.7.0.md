## Also ported during this sync

- **Smart-quote bug fix surfaced by the v0.7.0 fixtures:**
  `apply_smart_quotes_to_inline_tree` was pushing `' '` for `NodeValue::SoftBreak` into
  the concatenated text it ran the smart quote regex on.
  The `(?m)` regex’s `^` anchor never matched a sentence boundary across a soft break,
  so a second opening `"` after `."\n"` stayed straight.
  Now pushes `'\n'` (1 char either way; char-boundary accounting unaffected).
  Matches Python’s `coalesce_raw_text_nodes` which preserves `\n`.
- **Double-backtick code-span pattern** widened from `` `[^`]+` `` to `` `.+?` `` so a
  CommonMark double-backtick span wrapping content with internal backticks (e.g. ` `
  `code with spaces` ` `) is treated atomically by both `ATOMIC_CONSTRUCT_PATTERN` and
  `MARKDOWN_INLINE_PATTERN`.

### Reproducing the corpus parity sweep

`scripts/corpus-parity-check.sh` defaults its `[corpus_dir]` argument to
`attic/test-docs`, which is not tracked in this repo.
The sweep was run against a self-assembled corpus of 60 tracked repo Markdown files.
To rerun the same gate from a clean checkout:

```bash
# Build the release binary first.
cargo build --release --locked --all-features
# Assemble a 60-file corpus from tracked .md files (excluding the submodule).
mkdir -p /tmp/corpus
for f in $(git ls-files '*.md' | grep -vE '^repos/' | head -60); do
  cp --parents "$f" /tmp/corpus/
done
# Install the parity Python flowmark.
uv tool install flowmark==0.7.0
# Run the sweep (uses target/release/flowmark and reads parity version from Cargo.toml).
./scripts/corpus-parity-check.sh /tmp/corpus
```

### Corpus parity edge case

One file in the corpus, `docs/project/specs/done/plan-2026-02-17-exact-parity.md`, shows
two wrap-point differences in heavily-escape-laden inline code (e.g. ` `\`
`` — backslash-escaped backticks inside inline code spans). Both versions place valid semantic breaks; the breaks differ in heavily-escape-laden edge cases. This is the only file with a corpus diff (59/60 byte-identical) and is in a historical `done/`
spec that describes the very Rust escape-handling quirks it exhibits.
Tracked for follow-up investigation.
